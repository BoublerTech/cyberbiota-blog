Why I kept rebuilding my home lab

AriseOne, CyberBiota 1 and 2, and the fresh start that brought those experiments together in CyberBiota3.

By BoublerTechNovember 24, 2026Updated November 25, 20263 min read

Work covered: January to November 2026

I wanted to build my first home lab with open-source technology and use it to host my own apps and my own data.

AriseOne was where I started. A Bash script would ping machines and collect health information over SSH. An Ansible playbook could apply updates and report which hosts needed a reboot. By February, I had Nextcloud for files, Homepage for service links, and Zammad for tickets, with Proxmox hosting the virtualized parts.

Getting applications online also gave me machines to maintain. Kernel changes could mean NVIDIA driver repairs. Notes needed somewhere to live so the next fault didn’t start from scratch. I began moving Markdown instructions into Zammad’s knowledge base.

It was time for a fresh start

That’s the reason I moved on from AriseOne. I had tried CyberBiota 1 and 2 in the past: different versions of a lab, but not quite the lab I wanted. CyberBiota3 brought together what I had learned from them.

The first CyberBiota still used Proxmox, with ZFS storage and a Linux container for the monitoring tools. On February 13, the host was sending data to InfluxDB and Grafana could connect, but the panels were empty. The work was marked successful at 10:40 p.m.; the empty panels were recorded at 11:23, and work stopped at 11:34. The next day brought changes to the data-source IDs, dashboard JSON, and CPU queries.

That build also involved network and gateway experiments. By April, memory pressure and the friction of working through nested layers were part of the reason to change the layout. On April 7, CyberBiota 2 started with Ubuntu 25.10 and Docker on the hardware. A separate NVMe drive was allocated to persistent application data and local models, and the NVIDIA driver check could see the GPU.

I don’t have a complete migration record showing which application data carried through every rebuild. I can follow the platform changes, but can’t say every old service or file moved with them.

Keep the apps, and learn to look after them

By June, a new deployment exposed the work around the applications. Two image tags couldn’t be pulled even though the Compose file passed validation. Once those were corrected, Infisical and Homarr revealed separate configuration faults. The fixes recreated the affected app containers while leaving Postgres and Redis alone. Homarr went from HTTP 500 to its first-run setup screen; completing setup still needed a user test.

Backups became more concrete too. In June, selected repository files were restored into a separate folder and checked. In July, the backup timer ran on its own. Those were useful steps, but the local repository copy didn’t cover losing the laptop or recovering every database.

The November CyberBiota3.5 work took that further: host repairs, an encrypted external backup, an isolated PostgreSQL restore, and new AI-assisted operations roles. It still runs on one laptop. The goal is still the one I started with—my own apps and data—with more of the maintenance and recovery work tested along the way.

Start with AriseOne for the early scripts and services, or browse the journal for individual builds, fixes, and experiments.
