The rise of CyberBiota3

I wanted to host my own apps and data with open-source technology. AriseOne was my first try. CyberBiota3 brings together what I learned from the builds in between.

Events: January to November 2026Evidence: Owner recollection, historical records and dated change resultsEntry date: November 24, 2026

I wanted to build my first home lab with open-source technology and use it to host my own apps and my own data.

AriseOne was where I started. I had a Proxmox host and a few scripts. One script would ping machines and try to collect health information over SSH. An Ansible playbook could apply updates to the hosts in the inventory and tell me which ones needed a reboot. By February, the lab had a file service in Nextcloud, a dashboard in Homepage and a place for tickets in Zammad. Somewhere between those scripts and those services, my work went from getting one thing online to having several things to look after.

It was time for a fresh start

That’s why I moved on from AriseOne. CyberBiota 1 and 2 were earlier versions of a lab. CyberBiota3 is where I brought together what I learned from them. The changes in the logs give that idea a physical shape.

The first CyberBiota still ran on Proxmox. It used ZFS for storage and put the monitoring tools in a Linux container of their own. The host sent data to InfluxDB, but Grafana still showed empty panels. The February log has the whole turn: “success” at 10:40 p.m., empty panels at 11:23, and work suspended at 11:34. The next day, the notes show changes to the Grafana data source, the dashboard JSON and the CPU queries. Each change fixed a different part of the path between the host and the screen.

CyberBiota 2 changed the layout. After a run of gateway and network experiments, I moved off Proxmox. The April 7 record shows a clean Ubuntu 25.10 installation, Docker on the host, a separate NVMe drive for persistent data and models, and a driver check for the GPU. Those records tell me what was installed. They don’t give me a full list of which applications or data were carried forward from AriseOne and the first CyberBiota, so I leave that part of the story open.

What I carried into CyberBiota3

By June, I still wanted the same thing: my own apps and my own data. The records now show more of the work of looking after them. When the first Compose deployment couldn’t pull two image tags, the failure stayed in the notes beside the retry. When one app needed new configuration, its database and cache were left running. When the dashboard stopped returning HTTP 500 and opened its setup screen, the result said exactly that. There wasn’t a completed setup test to put beside it yet.

The clearest example for me is the backup. A snapshot was one step. The June check restored selected project files to a separate folder and verified that important files came back. In July, a natural timer run proved that the backup could run on its own, on that occasion. If I’m going to host my own data, I want to know which of those things I have actually checked.

This blog is where I’m putting those changes in order. Start with AriseOne to see what I had to work with, or open the change journal for what’s been changing since.
