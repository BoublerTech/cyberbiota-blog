Storage & recovery

The first backup I could show how to restore

A repository restore and a later scheduled run gave me two different pieces of recovery evidence.

By BoublerTechNovember 24, 20262 min read

If the machine disappeared, I’d need to know how to put it back together. The first CyberBiota3 backup exercise kept that question small: could I get the project repository back and read the files that explained how the lab was built?

I used Restic for a local encrypted copy. The result records both what was included and what was kept out. The project instructions and change records belonged in the backup. Known sensitive configuration and live runtime data were outside that scope. There was no reason to treat an encrypted copy as a reason to back up everything indiscriminately.

Open the copy and check it

After confirming a snapshot existed, the test restored it into a separate folder. That meant I could inspect the restored files without laying them over the working copy. The June report names the README, the operations instructions and the backup plan among the files restored. It records a separate check for excluded paths. Those are the details that let me follow the test. I can tell where the data was restored, what was expected to show up, and what the test deliberately left outside.

On July 6, the systemd timer ran the repository backup without a manual start. The receipt records an exit status of zero, a new snapshot timestamp and a successful Restic check. That’s useful because a recoverable copy today doesn’t mean the schedule will leave me another copy tomorrow. The scheduled run is also a different result from the June test, which actually put files back in a directory.

The two checks leave me with something I can work from: selected project files were recoverable, and a later backup ran on schedule. The result doesn’t tell me how to restore a live app database or bring the whole host back. And because the copy was local, it doesn’t cover losing the machine and its storage together. If I’m keeping my own data, each of those jobs deserves the same treatment as the repository: restore it somewhere safe, then check what’s really there.
