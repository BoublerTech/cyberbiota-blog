The first CyberBiota build and the empty dashboard

Proxmox was sending metrics to InfluxDB, yet Grafana showed empty panels. The next day’s corrections reveal where the checks fell short.

Events: February 13–14, 2026Evidence: Dated CyberBiota operations logEntry date: November 24, 2026

The first dated CyberBiota build log opens on February 13. Proxmox is the host, ZFS is the storage layer, and an LXC guest runs Docker, Ansible, InfluxDB, and Grafana. The entries say that metrics arrived in InfluxDB. That confirmed one part of the route from the host to the dashboard. It would take until late that evening to see how narrow that success was.

At 10:40 p.m. the log marked dashboard recovery successful after changes to the collector and monitoring configuration. At 11:23, the data was still in InfluxDB and Grafana could connect to the data source, but the panels were empty. At 11:34, the work was paused. The log says InfluxDB saw no queries during a later check. Possible causes were still open, including how the data source or browser was making the request. The order matters. The earlier success entry describes the state of the investigation at that point. A reader looking for a working dashboard needed the later entries too.

The next day’s work followed more than one lead. The log describes using explicit organization and bucket IDs in the InfluxDB data source. It also describes Grafana failing to load a provisioned dashboard until the JSON was normalized. The two metric sources needed different queries as well. The Proxmox host metrics used a different CPU field and scale from the Telegraf inputs. A dashboard designed for one source could quietly misread or miss the other. Those corrections are recorded separately, so I don’t have to pick a single cause for every symptom that night.

What can I show from the records? The host produced metrics. A database received them. Grafana had trouble provisioning and querying the right data, and the following log records targeted corrections. The records I have leave the original rendered panels and exact component versions incomplete. An independent check of the whole deployment would have to reopen those questions.

The lasting value of that build is the separation between each test. Check that the host emitted the metric, that the database stored it, that the query names the right field and units, and that the panel actually shows the expected result. If the first three work and the fourth fails, the journal still has a useful answer about where to look next.

Reading note
