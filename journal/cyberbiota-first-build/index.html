The dashboard that came up empty

The first CyberBiota build used Proxmox, ZFS, and Grafana. An empty dashboard exposed a gap between a connection and useful data.

By BoublerTechNovember 24, 2026Updated November 25, 20262 min read

Work covered: February 13–14, 2026

At 11:23 p.m. on February 13, the dashboard still had empty panels. Forty-three minutes earlier, the work had been marked successful. The data was in InfluxDB, and Grafana could connect to it. The screen was still empty.

I was building the first CyberBiota with Proxmox, ZFS storage, and a Linux container for the control tools. That guest ran Docker and Ansible alongside InfluxDB and Grafana. Proxmox sent its metrics to InfluxDB so I could view the host’s activity in Grafana.

Follow the data to the screen

Check that evening Result
Proxmox sending metrics InfluxDB contained host data.
Grafana connecting to InfluxDB The connection worked.
Dashboard panels Empty; a later check found no incoming queries.

The work stopped at 11:34 p.m. There was data to query, but the dashboard wasn’t turning it into a useful view.

The next day’s fixes addressed three different parts of that path. First, the InfluxDB data source was changed to use explicit organization and bucket IDs. Then Grafana reported a parsing error while provisioning the dashboard, so the dashboard JSON needed cleanup.

The CPU panels had another problem: the queries didn’t consistently match their sources. Proxmox host metrics and Telegraf metrics used different CPU fields and scales. A query suitable for one source could display the wrong value for the other. The panel queries had to match the data each panel was supposed to show.

The connection wasn’t the finished dashboard

The log records those corrections, but doesn’t preserve the final rendered panels well enough to reconstruct every result. I can describe the faults and the changes without claiming the whole dashboard was verified that night.

The empty screen is the important part of this episode. Checking the database and testing the connection had both helped narrow the fault. Neither had checked the thing I wanted to use: a panel showing what the host was doing.
