The first CyberBiota build and the empty dashboard

The host sent data and Grafana connected. I still had empty panels. Here is what the log says I checked next.

Events: February 13–14, 2026Evidence: Dated CyberBiota operations logEntry date: November 24, 2026

At 11:23 p.m. on February 13, the dashboard still had empty panels. Forty-three minutes earlier, the same log had marked the work as successful. The data was in InfluxDB, and Grafana could connect to it. The screen was still empty.

I was building the first CyberBiota with Proxmox, ZFS storage, and a Linux container for the control tools. That guest ran Docker and Ansible along with InfluxDB and Grafana. Proxmox sent metrics to InfluxDB. The idea was to see what the host was doing in Grafana without having to log in and check each piece by hand. Making it work meant following the metric all the way to a panel on the screen.

What each check told me

Part of the system What the February log shows
Proxmox to InfluxDB The host sent metrics, and the database contained data.
Grafana to InfluxDB Grafana could connect. That still left the queries and dashboard to check.
Grafana panels The late check found empty panels. The log says a subsequent check found no incoming queries, and the work stopped for the night.

The next day, the fixes came in three pieces. The InfluxDB data source was changed to use explicit organization and bucket IDs. Then the dashboard JSON was cleaned up after Grafana reported a parsing error during provisioning. After that, the CPU panels needed queries that matched their actual sources. The Proxmox host metrics and the Telegraf metrics did not have the same CPU field or scale. A CPU panel that worked for one could give the wrong answer for the other.

I can’t pin the whole evening on one bug. The first note that says “success” predates the empty-panel observation. The next day’s log describes what changed, but I don’t have the original rendered panels or exact software versions to reconstruct the whole result independently. That leaves enough to tell the story without turning an early check into an uptime claim.

When I look at a dashboard now, the question I come back to is the one that was missing at 10:40 p.m.: what did the panel actually show? A sample in the database helps me narrow down a fault. The panel is what I opened the dashboard to see.
