A valid Compose file and a failed deployment

The first CyberBiota3 deployment failed before images could pull. On the retry, two applications needed different repairs.

Events: June 26, 2026Evidence: First deployment report and dated retry resultsEntry date: November 24, 2026

The June 26 Compose check passed. Then Docker couldn’t pull two declared images, and the first deployment stopped. The file was shaped correctly enough to parse. The registry couldn’t supply the tags it named. Those checks were testing different things, and the first report leaves the pull failure in place as the outcome of the first attempt.

For the retry, the replacement image tags were checked against registry manifests. That removed the first blocker. Infisical then restarted repeatedly. Its encryption and authentication inputs were present in the deployment, but didn’t match the format and length the app expected. Correcting those inputs called for a targeted recreation of Infisical. Its Postgres and Redis containers were left in place.

Homarr failed on a separate path. Its route returned HTTP 500, and its service definition wasn’t passing a required encryption key into the container. The repair added that mapping and recreated just Homarr. The next route check returned HTTP 307 and went to the first-run setup screen. A reader can see the difference immediately: the old server error was gone and the setup route answered. There is no test of a completed setup in that result.

The remaining route checks tell a similar story at a wider level. Four selected routes responded with HTTP 200. The test proves those responses for the named check window. The next level of assurance would be an actual application job, such as signing in and doing a normal operation. The retry result shows the last completed step with enough detail for the next person to decide what to test.

The way I would read a deployment now is in that order. Can the configuration be rendered? Can the artifacts actually be fetched? Does the application initialize with the supplied inputs? Can a person finish the job they came to do? Those questions also put a limit on the repair. The broken image names did not justify recreating a database, and the missing Homarr input did not tell me anything about how Infisical had been configured. Leaving the healthy dependencies alone made the retry easier to interpret.

Reading note
