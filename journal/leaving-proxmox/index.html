Why I moved the lab off Proxmox

The move to native Ubuntu and Docker changed where storage, networking, and application responsibilities lived.

By BoublerTechNovember 24, 2026Updated November 25, 20262 min read

Work covered: March 6 to May 2026

The last night of the Proxmox build involved moving Linux guests to a new network, restarting them, and updating the reverse proxy. On April 6, the monitoring interface remained reachable and the proxy got responses from the backends it checked. The next morning, I was starting over with Ubuntu.

The network experiments before the rebuild

March had included a failed OPNsense restore and problems with a VyOS attempt. The gateway summaries don’t agree well enough to reconstruct every working configuration, but by April 6 the separate gateway experiments were being set aside in favor of Proxmox’s network layer.

Access to the host was a practical concern. On March 14, a change left me without SSH and with limited physical recovery options on a laptop normally run without a local console. If I couldn’t reach the host, a working application route elsewhere in the stack wouldn’t give me a way to undo the change.

The transition notes also describe memory pressure, competing workloads, and repeated friction getting commands and services through nested layers. Those were the reasons for simplifying the platform.

Ubuntu and Docker on the hardware

The April 7 installation record names Ubuntu 25.10. Docker ran directly on the host. A separate NVMe drive was allocated to persistent application data and local model storage, and the NVIDIA driver check saw the GPU.

Before After
Proxmox host with networked guests Ubuntu on the hardware, with Docker on the host
Storage organized through the virtualization layout A separate NVMe drive for persistent app and model data
Hardware checks spread across host and guests The native host could check the GPU directly

I could keep using containers with fewer layers between them and the hardware. Storage, application permissions, backups, and remote recovery also became responsibilities of that one Ubuntu host.

There isn’t a before-and-after benchmark to put a performance number on the change, or a restore list showing that every application’s data survived. Later May notes name Ubuntu 26.04, but don’t establish whether that step was an upgrade or another reinstall.

The change I can pin down is the April rebuild: Proxmox came out of this iteration, and native Ubuntu with Docker became the base for the next one.
