Publication method

Evidence & corrections

A historical record, a configuration file and a successful live test answer different questions. The portfolio labels them accordingly.

How to read claims

  • Historical account: a dated report or log says an action happened. It can be useful even when the underlying machine receipt is unavailable.
  • Reviewed result: the account was compared with a relevant saved output or change record. Its scope and date still matter.
  • Current state: requires a fresh check against the running system and loaded configuration. Historical success never establishes today's health.
  • Unresolved: sources conflict or the necessary test has not been reviewed.

Failures and later repairs

A later passing test does not erase an earlier failure. Where a change is corrected, the original and corrected observations stay separate. A disabled workflow is not the same as an uninstalled application, and a proposed automation is not a completed deployment.

Private evidence

Some original material contains internal paths, operational topology, credentials, private application data or conversations. This site uses carefully selected summaries and sanitized examples instead of linking to private archives that visitors could not access. Raw records are kept outside the public repository.

Corrections

When new evidence changes an article's conclusion, the article should receive a dated correction note and a link to the newer account. No correction log has been published yet because this site is still a review build.
