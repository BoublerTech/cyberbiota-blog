Deployment · Retrospective

A core deployment stopped before the stack came online

A valid Compose file still referenced image tags that could not be pulled. The recovery separated configuration syntax, artifact availability, application startup, and route behavior.

Events: June 26, 2026Evidence: Dated change reports and route checksEntry date: November 24, 2026

The operating problem

The first CyberBiota3 core-platform attempt did not reach a running stack. The configuration passed a syntax check, but some referenced container image tags were unavailable. This is a useful distinction for anyone building a service platform: a valid declaration is not proof that its dependencies can be fetched, started, or used.

The core platform records include Git-backed operations, workflow automation, identity-related services, and a dashboard. This case is about the June 26 deployment episode, not a claim that every service has remained healthy since then.

What changed

The registry lookup and the application checks failed independently. First, the replacement image tags were checked against their registry manifests. The next attempt exposed an Infisical restart loop. Its inputs had the wrong encoding or length. The correction replaced those inputs and recreated just the Infisical application, leaving its Postgres and Redis containers in place. Homarr’s HTTP 500 had a different cause. The Compose service did not pass in a required encryption key. Adding that mapping and recreating Homarr turned the error into the first-run redirect.

That recovery kept the dependency footprint small. A broader restart would have introduced more moving parts while the failures still pointed to individual application inputs.

Stage What the record established What it did not establish
Configuration validation The declared file could be parsed. Image tags existed or applications worked.
Image pull and startup Corrected artifacts could be obtained and services started in the retry. Every application completed its first-run setup.
Route checks Four selected routes returned HTTP 200. Homarr returned HTTP 307 to setup. Authenticated workflows, long-term stability, or a completed Homarr setup.

The 307 is not a failure to hide or a 200 to invent. It is a recorded first-run redirect. It narrows the result to reachable setup flow at that moment.

What this taught the operating process

Deployment acceptance needs layers: parse the configuration, verify artifacts, start services, check service-specific requirements, then exercise the user-facing path. A single green command cannot stand in for the whole sequence. The case also made targeted retries and explicit result tables more valuable than a broad “deployed” label.

Boundary: The reviewed evidence is a historical, bounded deployment result. It does not establish current health, data migration, or indefinite availability.
