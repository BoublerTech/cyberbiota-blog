Inside CyberBiota

One home lab, with applications to run and the operating work that comes with them.

The November 2026 build

The November 23–25 project records describe a single Dell G7 running Ubuntu and Docker, with separate system and data SSDs and an external USB backup. The lab has no second host or automatic failover. This is a dated project snapshot, rather than a live status page.

MonitoringVictoriaMetrics, Alertmanager, Grafana, Loki, Alloy, Blackbox Exporter
AI-assisted operationsOpenClaw coordinator, local Ollama/Qwen3, bounded role and tool design
RecoveryScheduled archives, encrypted USB copy, isolated restore tests

The 3.5 cutover added scoped role entries and a cloud coordinator while preserving legacy workflows. Selected live delegation and sandbox checks passed. The Python adapter suite was tested separately, and production remediation stayed disabled.

Before the bare-metal host

The early CyberBiota records describe Proxmox and LXC, ZFS storage, and a separate monitoring container. A Grafana connection came up while its panels remained empty. The dashboard entry follows the changes to the data source, dashboard, and queries.

Moving to Ubuntu and Docker

The April 7 record describes retiring the Proxmox iteration and starting an Ubuntu host for native Docker workloads. That summary names Ubuntu 25.10; later May records name 26.04. The records don’t settle whether that later change was an upgrade or reinstall, or which data carried through every earlier build.

Why I moved off Proxmox explains the transition.

What I check around an application

Getting a process to start is one step. I also need the intended route and authentication to work, data to persist, failures to be visible, and a recovery path with a defined test scope. Those responsibilities connect the layers above.
